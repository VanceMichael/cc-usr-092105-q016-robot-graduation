# 机器人毕业能力交接

保存机器人训练、能力认证和岗位接收所需的资料。杭州机器人学校与学校、工厂、海外接收方共建能力交接后台：接收方扫描毕业码获得岗位所需能力的**当前结论**（能做什么、在哪些场景测过、换件/升级/换场地后哪些能力待复验），学校保留从课堂到职场的完整历史。

## 资料范围

`contracts/domain.schema.json` 约束交换资料结构，`fixtures/domain.json` 提供一台导览机器人的完整虚构履历（入训、离线补传、多方签署认证、毕业赋码、部署试岗、退回返修换雷达、导航升级、证书撤销、两个接收方视图），`docs/domain.md` 说明领域对象、生命周期与不变量。`src/domain.py` 读取资料并校验档案不变量。

档案为每台机器人保存：

- 硬件配置（部件槽位、序列号、更换记录）与软件版本（固件/模型/语言包生效记录）
- 课程任务与多场景实战记录（学校、场馆、工厂、海外）
- 故障处置记录
- 能力证据（考核录像、评分表、演练记录，支持离线补传）
- 能力认证（范围、历次通过/撤销决定、多方签署、配置快照、当前复验状态）
- 毕业赋码（只能引用签发时点已通过且未撤销的能力）
- 部署交接（接收方、岗位所需能力、最小披露视图）
- 沿同一身份追加、按发生时间排序的完整时间线

核心规则：

- 毕业码只能引用已通过能力；证书撤销或能力降级后，扫码解析同步反映最新结论
- 硬件更换、模型升级、部署地点变化使相关能力进入待复验，复验通过沿原能力追加
- 训练资料可离线采集、联网后补传，时间线以采集时间为准
- 每项认证决定多人、跨机构签署
- 试岗反馈、退回返修、证书撤销沿原身份追加，不另建档案、不擦除历史
- 接收方只获得岗位所需能力的当前结论，部件序列号、签署明细、课程与故障记录不对接收方暴露

## 校验方式

在仓库根目录运行 `python3 -m unittest discover -s tests -v`。测试读取样例并核对：

- 样例档案满足全部不变量（赋码时点、证据真实、多方签署、配置快照、离线时序、变更复验、时间线追加、最小披露）
- 每条核心规则都有对应的反例用例，确认违规资料会被拒绝
